# Staging Environment Setup Guide

This guide will help you set up a complete staging environment for testing new features before deploying to production.

## Overview

**Staging Environment:**
- Branch: `staging`
- Web URL: `https://staging.crms-audy.pages.dev` (auto-generated by Cloudflare Pages)
- API URL: `https://crms-api-staging.<account>.workers.dev`
- Database: `crms-db-staging` (D1)

**Production Environment:**
- Branch: `main`
- Web URL: `https://it.audydental.com`
- API URL: `https://crms-api.<account>.workers.dev`
- Database: `crms-db` (D1)

## Setup Steps

### 1. Create Staging Database (D1)

```bash
# Create new D1 database for staging
npx wrangler d1 create crms-db-staging

# Output will show database_id, copy it
# Example: Database created with ID: abc123def456...
```

Update `apps/api/wrangler.toml` with the new database ID:
```toml
[env.staging.d1_databases]
database_id = "YOUR_STAGING_DB_ID_HERE"
```

### 2. Create Staging KV Namespace

```bash
# Create KV namespace for staging cache
npx wrangler kv:namespace create "CACHE" --env staging

# Output will show id, copy it
```

Update `apps/api/wrangler.toml`:
```toml
[[env.staging.kv_namespaces]]
id = "YOUR_STAGING_KV_ID_HERE"
```

### 3. Create Staging Queue

```bash
# Create email queue for staging
npx wrangler queues create crms-email-queue-staging
```

### 4. Run Database Migrations

```bash
# Apply all migrations to staging database
cd apps/api
pnpm exec wrangler d1 migrations apply crms-db-staging --remote
```

### 5. Add GitHub Secrets

Go to GitHub repository settings → Secrets and variables → Actions → New repository secret:

Add:
- `NEXT_PUBLIC_API_URL_STAGING`: Your staging API URL (e.g., `https://crms-api-staging.yourname.workers.dev`)

### 6. Optional: Seed Staging Database

Copy production data to staging (optional):

```bash
# Export from production
npx wrangler d1 export crms-db --output=prod-backup.sql

# Import to staging
npx wrangler d1 execute crms-db-staging --file=prod-backup.sql --remote
```

### 7. Deploy Staging

```bash
# Push to staging branch
git checkout staging
git push origin staging
```

GitHub Actions will automatically:
- Run migrations on `crms-db-staging`
- Deploy API to `crms-api-staging`
- Deploy web to Cloudflare Pages staging branch

## Usage

### Develop New Features

```bash
# Create feature branch from staging
git checkout staging
git pull origin staging
git checkout -b feature/new-feature

# Make changes...
git add .
git commit -m "feat: add new feature"

# Push and create PR to staging
git push origin feature/new-feature
```

Then create PR targeting `staging` branch.

### Test on Staging

1. Go to `https://staging.crms-audy.pages.dev`
2. Test your feature thoroughly
3. Check logs in Cloudflare dashboard

### Promote to Production

Once tested and approved:

```bash
# Merge staging to main
git checkout main
git pull origin main
git merge staging
git push origin main
```

## Useful Commands

### Check Staging Database
```bash
npx wrangler d1 execute crms-db-staging --command="SELECT COUNT(*) FROM work_items"
```

### View Staging Logs
```bash
npx wrangler tail crms-api-staging
```

### Deploy Manually to Staging
```bash
# API
cd apps/api
pnpm exec wrangler deploy --env staging

# Web
cd apps/web
pnpm build:cf
npx wrangler pages deploy .vercel/output/static --project-name=crms-audy --branch=staging
```

## Troubleshooting

### Issue: Database not found
**Solution:** Make sure you've created `crms-db-staging` and updated the ID in `wrangler.toml`

### Issue: API returns 500 errors
**Solution:** Check migrations were applied:
```bash
npx wrangler d1 migrations list crms-db-staging --remote
```

### Issue: Pages deployment fails
**Solution:** Make sure `NEXT_PUBLIC_API_URL_STAGING` secret is set in GitHub

### Issue: KV namespace errors
**Solution:** Verify KV namespace ID in `wrangler.toml` matches created namespace

## Maintenance

### Reset Staging Database
```bash
# Drop and recreate
npx wrangler d1 execute crms-db-staging --command="DROP TABLE IF EXISTS work_items" --remote
npx wrangler d1 migrations apply crms-db-staging --remote
```

### Sync Production to Staging
```bash
# Export production
npx wrangler d1 export crms-db --output=prod-sync.sql --remote

# Import to staging
npx wrangler d1 execute crms-db-staging --file=prod-sync.sql --remote
```

## Best Practices

1. **Always test on staging first** before merging to main
2. **Keep staging data separate** - don't mix with production
3. **Use feature branches** targeting staging
4. **Regular syncs** - sync production data to staging weekly (optional)
5. **Monitor logs** - check Cloudflare logs regularly
6. **Clean up** - remove old test data periodically
